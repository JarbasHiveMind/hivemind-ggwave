# AGENTS.md — `hivemind-ggwave`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

Zero-configuration satellite enrollment for HiveMind over data-over-sound. It
defines the pairing opcodes (`HMPSWD:`, `HMKEY:`, `HMHOST:`) and the
`GGWaveMaster` / `GGWaveSlave` primitives that let a hub and a fresh satellite
exchange a pairing password, an access key, and the hub's host address as
audio tones, using the [ggwave](https://github.com/ggerganov/ggwave) codec.
After enrollment the satellite saves a `NodeIdentity` and connects to the hub
over the normal encrypted HiveMind link — GGWave is only the bootstrap.
Orchestration (when to start, how to show the code, how to register the
client) is the caller's job, typically
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core). Part of the
[HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). Related repos:
[hivemind_bus_client](https://github.com/JarbasHiveMind/hivemind_bus_client)
(provides `NodeIdentity` and the websocket client used after pairing) and the
browser pairing tool at jarbashivemind.github.io/hivemind-ggwave.

## Layout / build / test

- Package module: `hivemind_ggwave/` (currently `__init__.py` + `version.py`
  — all logic lives in `__init__.py`). There is no test directory in this repo
  today; if you add tests, create `tests/` and add a `pytest` job to
  `.github/workflows/build_tests.yml` — do not silently rely on manual
  verification only.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[test]" --prerelease=allow`
- The `ggwave` audio codec and a working audio stack (mic + speaker) are
  required for any live round trip; see `docs/microphone.md`. Import and
  construction of `GGWaveMaster`/`GGWaveSlave` can be exercised without real
  audio hardware by mocking the `ggwave` calls.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is
  a bug to FIX at the source, not to work around with a pin downgrade.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- Speaks the HiveMind wire pairing protocol over audio, not a persistent
  connection — keep the three opcodes (`HMPSWD:`, `HMKEY:`, `HMHOST:`) and
  their payload formats wire-compatible with deployed masters/slaves; a
  satellite built against an older `hivemind-ggwave` must still be able to
  pair with a newer hub, and vice versa.
- Identity persistence: on receiving `HMHOST:`, the slave builds a
  `NodeIdentity`, sets `access_key` and `default_master`, and calls
  `identity.save()` (see `handle_host` in `hivemind_ggwave/__init__.py`).
  Never pair a device that already has a saved identity without an explicit
  re-enrollment path — pairing must not silently clobber existing credentials.
- `silent_mode` (master does not loop-broadcast the password; the caller
  triggers a single emission) is the production flow used by
  `hivemind-core`. Do not change its default behavior without checking that
  caller.
- This library only performs the bootstrap handshake; it holds no long-lived
  credentials or open connections itself, so it is not on the ongoing
  auth/ACL hot path — but the access key and password it exchanges become the
  credentials for the encrypted session that follows, so they must never be
  logged in full or exposed in error messages.
- The browser pairing tool (jarbashivemind.github.io/hivemind-ggwave) is a
  separate static site, not part of this package — do not assume its source
  lives in this repo.
